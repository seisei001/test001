# 坂口誠税理士事務所 SEO向け静的サイト(ひな形)

記事や固定ページを Markdown で書き、`build.py` で検索エンジンに読まれやすいHTMLに変換します。
生成先は `docs/apps/sakaguchi-site/`(ハブの「坂口誠税理士事務所(SEO版)」)。

## 構成
- `config.json` … 事務所名・公開URL・住所/電話・メニュー・noindexの切り替え
- `pages/*.md` … 固定ページ(index.md=トップ、strength/services/faq/contact)
- `posts/*.md` … ブログ記事(`_` で始まるファイルは対象外。`_template.md` が見本)
- `assets/site.css` … デザイン(JavaScript不要)
- `build.py` … 生成スクリプト(`python3 build.py`。`--drafts` で下書きも生成。`--preview` で下書きを含む非公開の確認用ページ `docs/apps/sakaguchi-preview/` を生成)

## 記事の追加手順
1. `posts/_template.md` をコピーして `posts/記事名.md` を作る
2. 先頭の title / description / date / tags / slug を書き、本文を書く
3. 公開する準備ができたら `draft: true` を削除する(下書きは公開されない)
4. `python3 build.py` を実行 → docs に出力 → commit & push

## 記事を書くときのSEOの目安
- 1記事=1テーマ。「誰の、どんな疑問に答えるか」を最初の2〜3行で書く
- タイトルは30字前後。検索されそうな言葉(例: 税務調査)を前のほうに入れる
- description は60〜120字。検索結果にそのまま表示される(`build.py` が長さを警告)
- 見出し(##)で論点を分ける。1記事に見出し3〜6個、本文は1,500〜3,000字が目安
- 関連記事や固定ページへのリンクを2つ以上入れる(`[対応分野](/services/)` の形)
- 内容を更新したら `updated:` の日付も更新する

## 公開前の確認(守秘義務・広告表現)
- 個別の案件を特定できる記述、顧客の実績・結果の記載(申告是認、不起訴など)は入れない
- 「必ず」「すべて」「No.1」などの断定・優位性の表現は避ける
- 税理士の業務広告に関する日本税理士会連合会の規程等に照らして確認する
- 記事末尾の「一般的な情報提供であり個別の助言ではない」という注記は自動で付く

## 本番公開するときの切り替え
1. `config.json` の `base_url` を本番のURLに変える(独自ドメインを取った場合はそのURL)
2. `noindex` を `false` にする(現在は検索に載せない設定)
3. 住所・電話・メール・郵便番号を `org` に入れる(地域検索の評価に直結)
4. 共有用の画像(1200×630)を用意し `og_image` にURLを入れる
5. 公開後、Google Search Console にサイトを登録し `sitemap.xml` を送信する
6. `hub_link` を `false` にして、ハブへの戻りリンクを消す
7. 連絡フォームを置く場合は、プライバシーポリシーのページを追加する

## 注意
- `robots.txt` はドメイン直下にあって初めて有効。独自ドメイン化するまで効果は限定的
- ハブ配下(`github.io/test001/apps/…`)のままでは、サイト全体の評価が育ちにくい
