# アプリハブ (test001)

このリポジトリは、複数のシンプルなWebアプリを1つのハブから使えるようにする実験場です。「作る → pushする → 使う」を繰り返しながら、並行して複数アプリを育てていくワークフローを想定しています。

## 公開URL

GitHub Pagesで公開しています(設定済み・変更不要)。

- ハブ: `https://seisei001.github.io/test001/`
- 各アプリはハブのカードをタップして開きます

iPhoneなどのSafariでハブを開き、共有ボタン →「ホーム画面に追加」でアプリのように起動できます。

## 新しいアプリを追加する手順

新しいアプリは既存のこのリポジトリ内に追加します(別リポジトリは作りません)。

1. `docs/apps/<アプリ名>/` フォルダを作り、`index.html`(必要なら `app.js` や `style.css` も)を追加する
   - 単一ファイルで完結する簡単なアプリなら `index.html` 1つだけでOK
   - ハブに戻れるよう、ヘッダーに `<a href="../../">← ハブに戻る</a>` を入れる(必須。その他の実装規約はスキル参照)
2. `docs/apps.json` に新しいアプリの情報を1件追加する

   ```json
   {
     "id": "アプリのid",
     "name": "アプリ名",
     "description": "簡単な説明",
     "path": "apps/アプリのid/",
     "icon": "絵文字アイコン"
   }
   ```

3. コミットしてpushすれば、公開ブランチにマージ後、数分でハブの一覧に自動で表示される(GitHub Pages側の設定変更は不要)

修正したいときは、該当する `docs/apps/<アプリ名>/` の中身を直接編集してpushするだけです。

## GitHub Pagesの設定

設定済みのため通常は変更不要です(Source: `Deploy from a branch` / Branch: `docs` / Folder: `/docs`)。
設定の変更はリポジトリ管理者権限が必要で、APIからは操作できません。

このリポジトリでは `docs` ブランチをデフォルトブランチ(=公開ブランチ)として運用しています。新しいアプリの変更はまず作業ブランチで作り、動作確認できたら `docs` ブランチにマージすると公開に反映されます。

主要アプリの補足:

### 📝 ひとことメモ (`apps/hello/`)

思いついたことをサッと記録できる最小構成のメモアプリ。localStorageに保存されます。ワークフロー確認用のサンプルアプリです。

### 🔗 URLリンク内容ビューア (`apps/url-viewer/`)

URLを改行区切りで入力(またはテキストファイルから読み込み)すると、1行目から順番にそのページの内容を表示するWebアプリです。

「内容を保管」を押すと共有シートが開き、「"ファイル"に保存」でGoogle Driveなど好きなフォルダに保存できます(共有非対応の環境ではダウンロード)。ファイル名はURL末尾の番号、無ければ本文1行目の「第N話」から `001.txt` の形で自動入力され、手で書き換えることもできます。

#### ローカルで動かす場合

1. 依存パッケージをインストール

   ```bash
   npm install
   ```

2. サーバーを起動

   ```bash
   npm start
   ```

3. ブラウザで `http://localhost:3000/apps/url-viewer/` を開く

4. テキストエリアにURLを1行ずつ貼り付ける(複数可)か、「テキストファイルから読み込む」で `sample-urls.txt` のようなURLリストファイルを選び、「読み込み開始」を押す

5. 1行目のURLの内容が自動で表示される。以降は次の4つのメニューで操作する

   - **次**: 次のURLの内容を表示する(次が無ければエラーメッセージを表示)
   - **前**: 前のURLの内容を表示する(前が無ければエラーメッセージを表示)
   - **内容を保管**: 現在表示中の内容(編集済みならその内容)をテキストファイルとしてダウンロードする
   - **終了**: ブラウザの「戻る」と同じ動作で前のページに戻る

6. 表示された本文は自由に編集でき、必要な部分だけ残してから「内容を保管」を押せば、その内容だけがダウンロードされる

##### 仕組み

- ローカルで`npm start`した場合は、サーバー側(`/api/fetch`)で対象URLを取得し、`cheerio`でHTMLから本文テキストを抽出してからブラウザに返します(CORSに引っかからない)。
- GitHub Pagesなどサーバーが無い環境では、`/api/fetch`が使えないことを検知して自動的に公開のCORSプロキシ経由で取得し、ブラウザ内(`DOMParser`)で同じロジックの本文抽出を行います。
- 読み込んだURLリストと現在位置は`localStorage`に保存されるため、ページを再読み込みしても続きから再開できます。

**注意**: 公開のCORSプロキシは無料・非公式のサービスで、混雑時に失敗したりレート制限にかかることがあります。

### 🧍‍♀️ VRMアバター (`apps/avatar/`)

自律的に呼吸・瞬き・仕草・歩行・座る、といった一通りの行動をするVRM女性アバターをただ眺めるページです。操作は視点のドラッグ回転のみ。

- `lib/` — `seisei001/test001` の `resources` ブランチにある `autovrm` ライブラリ本体(three.js製、フレームワーク非依存)
- `animations/` — 自律行動用のモーション素材一式(出典・ライセンスは `resources` ブランチの `autovrm/README.md` を参照)
- `models/AvatarSample_A.vrm` — `seisei001/vtubet` から持ち込んだVRoid公式サンプルモデル(商用利用可・クレジット不要。詳細は `models/LICENSE.md`)
- `three.js` / `@pixiv/three-vrm` 等はビルド不要で使えるよう、`index.html`内のimport mapでCDN(jsdelivr)から読み込んでいる

このアプリの本体である`autovrm`ライブラリは今後も改修していく予定。ライブラリ自体を直す場合は、まず`resources`ブランチ側で直してから、この`apps/avatar/lib/`と`apps/avatar/animations/`に反映すること。
