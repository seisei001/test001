# 階層世界シミュレーター 作成方針(全体構成)

作成者: 全体を指揮するエージェント。サブエージェントを立てる前に、方針を決める文書。

> **注意(2026-11-02)**: 最新の統合設計は OVERVIEW.md。この文書は経緯の記録で、食い違う所は OVERVIEW.md を優先する(§2.1/2.2/4/5/7は旧案を含む)。

## 1. 設計思想(原則)
1. **世界は1枚の世界地図から決まる。** 下位の地図は、上位の地図の値と種から決まる。上から下へ降りる。(下位が上位を決めるのではなく、上位が下位を縛る)
2. **全ての層は同じ仕組み(自己相似)。** どの層も「ある広さの地図(マスの集まり)」であり、1マスは、下位の1枚の地図を要約した絵である。層が違っても、持つ情報の種類と更新の仕組みは同じ形にする。
3. **層の数が決まれば、1枚の下位地図の広さは自然に決まる。** 最大(世界のマス)と最小(兵1人)の大きさの比を、層の数で等しく割ったものが、1層ごとの縮み率になる。縮み率が、下位1枚の地図の幅になる。
4. **見える絵と、動くシミュレーターは同じ位置情報を使う。** 描画のために別の座標を持たない。描かれた位置がそのまま、軍の位置であり、辺の移動の難しさの位置になる。
5. **上下は常に互いを縛る。** 上から下へは「制限」(気候、経済、交通網、季節)。下から上へは「積み重ね」(辺の移動の難しさ、損害、備蓄の減り、道の傷み)。どちらか一方だけの流れにしない。
6. **層ごとに別のシミュレーターと別の時間の刻みがある。** 世界の層は日・月で動き、戦場の層は秒・分で動く。受け渡しは、決まった窓口(辺の情報と集計値)だけで行う。
7. **全ては動的に変わる。** 地形の変化(荒廃、開発、荒れた道)、地名、持ち主、通行のしやすさは、シミュレーターが変える。変化は、変わった所だけを記録する。
8. **細かい所は、見ている所だけ作る。** 世界全体の最下層までは持たない。見ている所と軍が動く所の周りだけ詳しく、その外側は上位の要約のままにする。
9. **「ビット単位でどう見えるか」を基準にする。** データの1単位は、最下層では兵1人の大きさになる。層が上がっても、見え方は「その層の1マスが1つの絵」になる。
10. **同じ種なら同じ世界(再現できる)。** ただし、種を変えれば、毎回違う世界と違う展開になる。

## 2. 全体の構成(層の考え方)
### 2.1 層の数と縮み率(自然に決まる)
最大のマスを、世界図の1マス(約300km、仮)、最小のマスを兵1人(約1m)とすると、比は約30万倍。
層の数を変えると、縮み率(=下位1枚の地図の幅)が変わる。

| 層の数 | 縮み率(下位1枚の幅) | 下位1枚のマス数(目安) | 各層のマスの大きさ |
|---|---|---|---|
| 5層 | 約23 | 約400 | 300km / 13km / 570m / 25m / 1m |
| **6層(有力)** | **約12** | **約115** | **300km / 24km / 2km / 160m / 13m / 1m** |
| 7層 | 約8 | 約50 | 300km / 37km / 4.5km / 550m / 67m / 8m / 1m |
| 8層 | 約6 | 約27 | |

有力は6層。理由: 24km≒大軍の行軍1日、2km≒戦場、160m≒百人隊、13m≒組(10人程度)、1m≒兵1人、が、**自然に各層に乗る**。
実験で確かめること: 5・6・7層で、軽さ(データ量・計算時間)と、層をまたぐ連携の自然さを比べる。

### 2.2 層の役割(6層の場合の仮置き)
| 層 | マスの大きさ | 見えるもの | 動くシミュレーター | 時間の刻み |
|---|---|---|---|---|
| 0 世界 | 約300km | 7大陸、気候帯、海流 | 気候、季節、世界の経済 | 日〜月 |
| 1 地方 | 約24km | 山脈、川、町、峠、国境 | 経済、補給、交通網、軍団の移動 | 時間〜日 |
| 2 戦域 | 約2km | 地形、道、砦、村 | 縦隊の行軍、補給部隊、開発・焦土 | 分〜時間 |
| 3 戦場 | 約160m | 部隊の隊形、遮蔽物 | 隊どうしの接触、判断AI、士気 | 数十秒 |
| 4 隊 | 約13m | 組、旗、地面の起伏 | 隊形、指揮、白兵 | 数秒 |
| 5 兵 | 約1m | 兵1人 | 兵の動き、見た目 | 1秒以下 |

### 2.3 上下の結びつき(窓口)
- **上から下へ(制限)**: 上の層のマスの値(高さの基準、地形の種類、肥沃度、持ち主、気候、季節、荒廃)が、下の層を作るときの「枠」になる。下の層は、上の値を守りながら細部を足す。
- **下から上へ(積み重ね)**: 下の層の辺の移動の難しさと、備蓄・損害・道の傷みの集計が、上の層のマスと辺の値になる。
- **辺の情報**: 隣り合うマスの間に、移動の難しさ(兵種ごと)、道の種類、橋、関所、混雑、季節の影響を持つ。上の層の辺の値=下の層の辺の積み重ね+上からの制限。
- **循環を止める決まり**: 上下の更新は、順番を決める(上の制限→下が動く→下の集計が上へ→次の上の更新)。1回の更新での変化量に上限を付ける。受け渡す値は「前の時点の値」を使う。

### 2.4 見え方
- 各層に「その層の見え方」を持つ(世界層は輪郭と気候色、地方層は地形と道、戦場層は隊形、兵の層は兵の絵)。
- 斜めから見た立体は、各層の高さをその層の立体として描く。下の層の立体は、上の層の位置の上に載せる。拡大の途中では、2つの層をなめらかにつなぐ。
- 高さは上の層に従う(下の層は、上のマスの高さの周りに細部を足す)。

## 3. 作り方の方針
1. **順序**: (a) 全体構成を決める(この文書) → (b) 層ごとの詳細設計(サブエージェント)→ (c) 六角形の表し方を、上位構成が決まってから決める → (d) 縦に1本通した最小の実装(世界→地方→戦域→戦場→隊→兵)→ (e) 各層を厚くする。
2. **六角形の表し方は、最後に決める。** 決め手になる条件は、層の数と縮み率(§2.1)から出る。
3. **確かめ方**: 層の数、縮み率、描画方式は、実験の数字(データ量、計算時間、上下のつながり)で決める。
4. **作る場所**: 地図ラボとは別の新しいアプリとして作る。
5. **サブエージェントの使い方**: 方針を渡し、層ごと・要素ごとに設計と実験を任せる。全体の食い違いは指揮するエージェントが調整する。分からないことはユーザーに質問する。

## 9. 道・運河・峠の決め方(11/1 ユーザー指示)
13. **交通網は交通網シミュレーターが動的に決める。** 峠や道を上位で固定しない。
    - 最下位層の地形(傾き・崖・川の落差・川幅)が通りやすさの元になる。川は別モデルで作り、交通網はそれを使う。落差の大きい川は運河に使えない。
    - 道は通行量が多いほど育ち、使われなければ傷む(動的)。地形上作りやすい所に自然にできる。
    - 経路は上位の辺の費用で大づかみに決め、必要な所だけ下位で細かくたどる(層をまたぐ経路探索)。峠は「最も安い渡り方」として自然に現れる。
    - 最適化する層は、地方層(層1)付近を第一候補とする(要実験)。

## 10. ターン制(11/1 ユーザー指示)
14. **計算はターンで進める。** 各層に自分のターンの長さがある(世界1日/地方2時間/戦域10分/戦場1分/隊6秒/兵0.5秒、work/sims.md)。上の1ターンの間に下が決まった回数だけ進む。
    - 1ターンの結果は内部で確定し、画面ではその間の動きをなめらかに再生する(ユーザー選択)。自動で進む速さは変えられる。
    - 利点: 結果が再現でき、要約と詳細の食い違いが出ない。交通網・経済は上位の長いターンでゆっくり動かす。
    - 注意: 士気などの閾値を越える時刻は、ターンの中で補間して決める(ターン境界に丸めない)。

## 11. 交通網の実験結果(work/transport.md)
- 峠は自然に現れる(2〜4本に集まる)。階層探索(地方層で大づかみ→戦域層で回廊)は平均+0.1〜0.3%で、探索量は約3割。
- 地方層のマスの代表点は「中心に近い歩ける陸」にする(中心が海や崖だと通れなくなる)。

## 12. 水の計算の置き場(11/1 ユーザー指示)
15. **水位・流量は交通網シミュレーターが毎ターン計算する。** 天候シミュレーターは雨と蒸発の倍率(と大雨)を出すだけ。複雑にしない(湖ごとに水量1つ+毎ターンの流量)。大雨のターンは交通網側で水を計算し直し、渡れる所・舟の通れる所・経路を更新する(work/transport.md 追補)。

## 13. 災害(11/1 ユーザー指示)
16. **災害は天候シミュレーターが起こす。** 浸食は入れない。
    - 洪水: 川の流量が平年の2.5倍を超えたら、川と隣の低い所を浸水にする。
    - 土地の崩壊: 湿りと急斜面で確率的に崩れ、土は下の隣へ移る。地形の変更は差分として積む。
    - 交通網側は、地形が変わったら川・湖・流れを作り直す(12〜24ms)。堰止め湖や道の喪失は結果として現れる。
    - 下位層は、親の差分を取り込んで該当ブロックを作り直す(未実装)。実験結果は work/transport.md 追補2。

## 17. 地変イベントと大雨の道の変動(2026-11-01 決定)
- 地変イベントは、場所も種類も乱数(世界の種=seedから決定)で決める。種類は次の10種。
  1 噴火(盛り上がり+灰) / 2 巨大地震(沿岸の沈下) / 3 大津波(海岸の浸水) / 4 山体崩壊 / 5 大地すべり / 6 天然ダム(堰止め湖→のち決壊) / 7 断層の段差(地割れ) / 8 隆起(土地が持ち上がる) / 9 陥没(陥没湖・カルデラ) / 10 大氾濫による川筋の変更
  - 1つの世界の歴史で2回程度起こし、同じ種類は続けて選ばない。
  - 場所に合わない種類(内陸で大津波など)は引き直す。
  - 起きたら大事件として上位層へ即報告。
- 大雨による道・橋・川の変動は小規模にとどめる(洪水の通行コスト・道の傷みは今より弱める。地形そのものは大きく変えない)。
- 深層崩壊・天然ダムは、地変イベントとは別の「大雨の延長」としては作らない(必要になったら再検討)。

## 18. 開発の流れと地図の地政学(2026-11-02 ユーザー指示)
- 流れ: ①地図のランダム作成(地政学を含む)→②交通網シミュレーター→③経済→④人口動態→⑤地形の決定(農地・開拓・鉱山・都市化など人の手が入った地形)→⑥軍・街の規模の決定→⑦糧食→⑧地図と全シミュレーターの情報の調整。
- 地形を雑にランダムで作らない。地図作成の合格条件に地政学の検査を加える:
  1. 自然な地域のまとまり(山脈・大河・海峡で区切られた複数の地域がある)
  2. 要衝(峠・海峡・河口・渡河点が適度にある。ありすぎず、なさすぎず)
  3. 自然国境(各大陸で、境界になる地形がある)
  4. 食料を生む平野・盆地が各大陸にある(人口の核になる)
  5. 資源(山・森・海岸)が偏りすぎず、足りない所もある(交易の動機)
  6. 港の候補と交易のつながり(海岸線・河口が適度にある)
  7. 孤立と接触の釣り合い(完全に孤立した大陸ばかり/全部陸続き、を避ける)
- 川・湖・道・街は交通網シミュレーターが作る。表示(viewer)は結果を読むだけで、独自に作らない。川幅はメートルで持ち、集水量から決める。

## 19. 地政学シミュレーター(2026-11-02 ユーザー指示)
- 地政学は「検査」ではなく**シミュレーター**にする。§18の合格条件(検査)は入口の足切りとして残し、本体は次のとおり。
- 位置づけ: 流れの最後(人口動態・糧食・軍・街の規模が出たあと)に動く。入力は、地形・交通網(川・道・峠・港)・経済・人口の分布。
- 国や領主は決めて置かない。**人口が集中した所から自然に生じる**:
  1. 人口の山(核)を見つける。核は人口・食料・交易の便で大きさが決まる。
  2. 核の大きさに応じて階層が生じる: 豪族(村・郷)→郡→都市(城下)→国。大きな核ほど上の階層になる。
  3. 支配圏は、交通網の通行コスト(歩く・荷を運ぶ)の近さで決まる。山・大河・海峡で自然に切れ、峠や渡河点・港が要衝になる。
  4. 領主が成り立つ条件(食料を賄える・守れる・交易で稼げる)を満たさない所は、育たず吸収される。どんな領主が成立するかは地政学で自然に決まる。
  5. 支配圏の境は固定せず、ターンごとに人口・軍・糧食の変化で動く(§10)。
- ファンタジーなので、魔物・竜・聖地など現実にない要素が「要衝」「脅威」「資源」として入ってよい。成立の仕組みは同じで、条件だけが増える。
- 実装の順: 交通網シミュレーターの移植 → 人口動態(核の抽出) → 領主の成立と支配圏 → 表示(境界線・名前)。
- 出力は国・郡・都市・豪族の木構造(上位層ほど大づかみ)で、各層の表示にそのまま使う。

## 20. 空を飛ぶもの(龍など)と交通網(2026-11-02 ユーザー指摘)
- 交通網シミュレーターは「道・川・峠」を作る人と荷の網だけを扱う。**空を飛ぶもの(龍・飛竜・鳥の魔物など)は交通網に入れない。**
- 移動のしかたごとに、通行コストの表を別に持つ(移動様式): 徒歩 / 荷駄・馬 / 舟(川・海) / 飛行。
  - 飛行は地形の起伏・川・海を無視し、直線に近い。代わりに「航続(1ターンで飛べる距離)」「巣(戻る所)」「体力・餌」の制約を持つ。
  - 風・嵐・高山の薄い空気など、天候で効きが変わる。
- 龍は、道を使う存在ではなく**脅威圏**として地政学に入れる: 巣を中心に、航続の範囲が危険な圏になり、そこでは交通網の道の通行コストが上がる(襲われる)・街の成立が難しくなる・逆に「竜を鎮める」領主が力を持つ。
- 交通網シミュレーターの内部は変えない。飛行は別の小さな計算(巣・航続・脅威圏)として、地政学シミュレーターが読む。

## 21. 移動手段は「データで定義する」(2026-11-02 ユーザー指示: もっと柔軟に)
- 移動手段(徒歩・馬・舟・龍・飛空艇・航宙船・転移門など)をコードに埋め込まない。**1つの手段 = 1行のデータ**で定義し、足せば増える。
  - 項目: 地形ごとの通行コスト(通れない所は無限大) / 1ターンの航続 / 速さ / 積載 / 拠点(巣・港・発着場・門)が要るか / 燃料・餌・魔力などの消費 / 天候の効き / 必要な設備(道・川・空港など)と、その建設・維持費。
- 交通網シミュレーターの役目は「どの手段でも、拠点と設備と通行コストから、行ける範囲と道筋を出す」こと。道や川は、そのうち**設備を地表に作る手段**(徒歩・馬・舟)の結果にすぎない。
- 空を飛ぶ手段(龍・飛空艇)は地形を無視し、航続と拠点で制約される。航宙船は、世界の外(軌道)を経由する手段として扱い、発着場のある所どうしだけが結ばれる。大量輸送でき、設備と燃料に費用がかかるため、経済・地政学に強く効く。
- 敵になる手段(龍の脅威圏)も同じ表で扱う。持ち主の違いは、味方が使うか、脅威として圏を作るかだけ。
- 技術・魔法の発展(新しい手段の登場)は、表に行が増える出来事として扱い、交通網・経済・地政学が次のターンから自動で読み直す。
- 世界の設定(剣と魔法/宇宙時代など)は、最初に使える手段の表で決まる。§19の地政学は、この表がどうなっていても動く。

## 22. 人口動態は「設定+イベントの増減」だけ(2026-11-02 ユーザー指示)
- ファンタジー独自の制約・拡張(種族、寿命、出生の癖、魔物の脅威、魔力による食料・病、聖地の恩恵など)は、**シミュレーターにせず、最初に決め打ちの設定として持つ**。気候(§天候)と同じ考え方。
- 設定から決まるもの: 各マスの人口の上限(食料・水・交通・安全で決まる収容力)、標準の増え方・減り方、種族ごとの癖。
- 人口動態シミュレーターの仕事は1つだけ: **イベント(戦争・飢饉・疫病・災害・移住・開拓・魔物の襲来・技術の登場など)で人口がどう増減するかを出す。** 平時は設定の標準の増減に従い、イベントのときだけ動かす。
- 出力は「人口」と「その中の兵になりうる数(動員可能数)」。軍・街の規模の決定(§18⑥)は、この動員可能数を元に兵数を出す。

### §22 追記: 自然増減は単純な規則にする(2026-11-02 ユーザー指示)
- 自然増減は「シミュレーター」と呼ぶほどのものにしない。**周りの状況から、単に増えたり減ったりするだけ。**
  - 肥沃な土地で、治世が安定していれば増える。
  - 増えすぎて食料(糧食)が足りなくなれば減る(上限は食料の収容力)。
  - 荒れた土地・不安定な治世・脅威(魔物・戦争)があれば増えにくい、または減る。
- 1マス・1ターンごとに「収容力に対する今の人口の比」と「肥沃さ・治世・脅威」を見て、増減の割合を決めるだけ(段階表で足りる)。人口どうしの相互作用や年齢構成などは持たない。
- 大きな動きはイベント(戦争・飢饉・疫病など)が起こす。自然増減とイベントの2つだけで人口は動く。

## 23. 経済の設計: 食糧が中心・産業は武器と兵の強さ・何もしなければ循環(2026-11-02 ユーザー指示)
- **食糧(糧食)は経済の中心。** 別々のシミュレーターにせず、経済の中の主役として持つ(§18⑦は経済に統合)。人口の収容力・自然増減(§22)・軍の維持・街の大きさは、すべて食糧の収支から決まる。
- **産業は、武器の産出量と兵の強さに関わる。** 産業(鉱山・工房・資源)→ 武器・装備の量と質 → 兵の強さ。兵の数は人口の動員可能数(§22)、兵の強さは産業が決める。
- **経済は、何もしなければ全てが循環するように設計する(定常状態)。**
  - 生産された物(食糧・資源・製品)は、消費・輸送・保管の中でぐるっと回り、**何も起きなければ総量も分布も変わらない**(増え続けも枯れもしない)。
  - 増減や偏りは、イベント(戦争・飢饉・災害・新しい道・新技術)か、人口の変化が起こしたときだけ生じる。
  - 確かめ方(検査): 何も起こさず多数ターン回して、備蓄・人口・物流量が動かないことを毎回確かめる(固定点テスト。coupling/check.js と同じ考え方)。
- **循環と交通網シミュレーターは厳密に相互関連する。**
  - 物の流れ(食糧・資源・製品)は交通網の道・川・港の上を、移動手段の通行コストと積載で運ばれる。経済が必要とする輸送量が、交通網の道の育ち(通行量が多いほど育つ、§9)を決める。
  - 逆に、道・橋・峠・川の状態(災害での寸断、大雨、新設)が、運べる量と費用を決め、経済の循環の形(どこで余り、どこで不足するか)を決める。
  - 受け渡しは同じターンで二重に数えない(OVERVIEW §4 の順序規則)。経済→交通網は「必要な輸送量」、交通網→経済は「運べた量と費用」。
- **交通網シミュレーターは全体の要。** 水(川・湖)、道、移動手段、物流を通じて、経済・人口・糧食・軍・地政学のすべてに効く。実装の優先順位はこれを土台に置く。

## 24. 交通網の物流: 運搬具の表と輸送費(2026-11-02 ユーザー指示)
- 運ぶ物は食糧・資源・製品・**武器・兵**。物流は交通網シミュレーターの仕事(§23)。
- 運搬具は表の1行(荷車・馬車・飛空艇・ドラゴン・大型船舶・小型船 …)。それぞれ長所短所がある(速さ・積載・必要な設備・消費・別払い)。
- 輸送費(運んだ物から消える量):
  - **舟**(大型・小型): 運んだ量の40%。
  - **陸路**(荷車・馬車): 運ぶ人の数の2倍。少数で運べば安い。
  - **飛空艇・ドラゴン**: 運んだ量の2/3。さらに魔力など別の資源を別途支払う(運用コストが高い)。
- 武器は、届いた先の兵の**士気と練度を上げる**(産業→武器→運ぶ→兵、§23)。兵そのものも運べる(輸送中は糧食を食べる)。
- 実装: sekai-hex/transport.js の CARRIERS と haul()。数字は仮置きで、運搬具ごとに載せる量・速さ・乗員は後で調整する。
- 未確認の解釈: 「別途支払う」を魔力などの別資源として扱った。陸路の「人数の2倍」は1回の輸送ごとの消費として扱った。

### §24 訂正(2026-11-02 ユーザー指示): 届く割合
- 荷車: アクシデントが無ければ、**運ぶ人の食糧として消費される分以外の全て**が届く(消費は運ぶ人の食糧だけ)。
- 馬車: 6割が届く(消費40%)。
- 舟(小型船): 6割が届く(消費40%)。
- 大型船舶: 7割が届く(消費30%)。
- 飛空艇・ドラゴン: 1/3が届く(消費2/3)+魔力など別払い。
- 前の「陸路は運ぶ人数の2倍を消費」は荷車の「運ぶ人の食糧」(人数×2)として残し、馬車は上記の割合に置き換えた。

## 25. 割引率はゲームの釣り合いで決める/ファンタジーの要素/編成と階級(2026-11-02 ユーザー指示)

### 25.2 運ぶ物と運搬具

## 26. 領主の課税・土地の価値・魔導石(2026-11-02 ユーザー指示)
### 26.1 課税(領主の権利)
- 領主になると**課税権**が与えられる。税率は自由に決められる。
- 高すぎる → 民が逃げる(人口が減る、§22のイベント扱い)。
- 低すぎる → 兵が雇えない → 治安が悪化 → 生産性が下がる → 兵が弱兵化する。
- **ちょうど良い税率は4割**(釣り合いの中心。ここからずれるほど悪い方へ効く。数字はゲームの釣り合いで調整する)。
- 税収は経済(§23)で、領主の兵(雇う数と質)・施設・交通網の維持に回る。人口・治安・生産・兵の強さが、税率を介して相互に効く。
### 26.2 土地の価値(マスごとの属性)
- 土地は一様でなく、価値の種類を持つ。マスごとの属性として持ち、地形・気候から決まる設定(最初に決め打ち、§22と同じ考え方)。
  - **肥沃な土地** / 作物の産出が少ない土地(食糧、§23)
  - **運搬に向く土地** / 向かない土地(交通網の通行コストと運搬具の効き、§24)
  - **兵の移動が可能な土地** / そうでない土地(軍の通行)
  - **産業の盛んな土地**(鉱山・工房・資源。武器の量と兵の強さ、§23)
  - ほか、様々な価値(港・要衝・聖地など。地政学 §19 が読む)
- 領主の力は、持つ土地の価値の組合せと、課税の釣り合いで決まる。
### 26.3 魔導石
- **魔道具(魔導具兵器・魔法砲・魔法障壁など)を使うには魔導石が必要**。魔導石は魔力の別資源として物流・経済に入る(飛空艇・ドラゴンの別払い=魔力も同じ、§24/§25)。
- **魔導石は魔物を駆除すれば入手できる。** 魔物が多い土地は脅威だが、魔導石の産地でもある(脅威圏 §20 と対になる)。駆除する軍事行動に経済的な動機が生まれる。

## 27. 層ごとの意味と、最大拡大の姿(2026-11-02 ユーザー評価を受けて)
### 27.1 ユーザー評価(v0.34)
- 国境は、地図の上で勝手に引いてよい(シミュレーションで導かない)。
- 絵図鑑の地図としては魅力が出てきた。ただし立体感はまだ。
- **層ごとに見え方が違うだけで、層ごとの「意味」が感じられない。**
- **最大拡大の街はまだ絵。** 街の見取り図どおりに家が建っていない。最大拡大では**人の大きさがマス目**のはずなのに、小さすぎる。
### 27.2 層ごとの意味(「何を決める地図か」)
| 層 | 画面で見るもの | 意味(ここで決めること・読み取れること) |
|---|---|---|
| 0 世界 | 大陸・気候・国の色と名前 | 国どうしの力関係、大きな交易路、気候帯 |
| 1 地方 | 都市・郡・街道・川・国境 | 領地の経営(食糧の過不足、税、物流)、軍団の進路 |
| 2 戦域 | 村・畑・森・砦・道・橋 | 補給線、峠・渡河点、陣地を取る場所 |
| 3 戦場 | 部隊(百人隊)の隊形・地形の遮蔽・建物 | 戦闘の配置、隊どうしの接触 |
| 4 隊 | 組(約10人)・旗・個々の家・柵 | 隊形、街の通り・区画 |
| 5 兵 | 兵1人=1マス、家=複数マスの間取り | 兵と住民の位置・動き |
- 各層は、**その層で意味のある情報だけ**を描く(上位の情報を細かくしただけにしない)。例: 層0は国の力関係、層3は兵の隊形、層5は人。
- 層ごとに、パネルと凡例も変わる(その層で押せる・選べるものが違う)。
### 27.3 最大拡大(層4〜5)の街
- 街は**見取り図(区画・通り・建物の位置)をデータで持つ**。層2〜3の街の絵は、その見取り図の要約。層4〜5では、見取り図どおりに家・通り・広場・城壁を描く(絵を貼らない)。
- **層5は1マス=人1人(約1m)。** 人・兵・馬・荷車・魔獣は、マスの大きさを基準に描く(今の絵は小さすぎる)。家は何十マスにもなる大きさ。
- 見取り図は街の型(sprites.jsの17種)ごとに持ち、同じ種=同じ街並み。人口が増えると家が増え、城壁の外へ広がる。
- 下位層へ降りても、国・領主・税・食糧は上位と同じ値を引き継ぐ(要約と詳細が食い違わない)。

### §27 追記3: 街並みの作り方(2026-11-02 ユーザー指示: ゲームを参考にやり直す)
- 街の見取り図は、街づくり系ゲーム/中世都市ジェネレーターの作り方にそろえる: ①中心に広場 → ②Voronoiで区画(区)を作る(格子型の街は格子の街区) → ③通りの幅だけ区画を縮める → ④区画を長い辺の向かいで繰り返し割って建物の敷地にする → ⑤敷地に向きつきの長方形の建物を置く。中心ほど小さく密、外ほど大きく疎。ときどき公園。
