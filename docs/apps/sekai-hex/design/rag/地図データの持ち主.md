# 地図データの持ち主と範囲(何を地図が持ち、何を他が持つか)

## 今の確定
- [確 11-28 05:55 ユーザー] ①気候シミュレーターは水の発生を制御する。②気候シミュレーターが出した様々なデータは、直接地図上にデータとして落とし込む(例: 洪水で水が流れた後の土地は泥土になる。風の影響で土地の整備度が下がる=ここはまだ未定)。③交通網シミュレーターは「どの土地がどう連結するか」のシミュレーター。④泥土化した土地は通り抜けられず、整備が進むまで交通網が遮断される。(ユーザーの質問「そんな感じにはできない?」)
- [確 11-24 23:17] 魔力・地脈は川と同様にシミュレーターとの連携による(ただしデータは世界地図として保有する。11-25 05:48)。川は戦場以下でポリゴンの部品にする(世界地図〜戦域地図は絵で代用。11-25 05:41 ユーザーで修正)。魔力だまり・地脈は今後ポリゴンの部品にする(予定)。
- [確] 水の高さ(海・湖・川の水面と底)=交通網・天候。地図(絵+ローポリ)は持たない。理由(ユーザー 11-24 23:17): 水の高さは動的で、洪水など天災により水位が地図のどの位置に来るか流動的なため。
- [確] 地図データは要素を含めて作る(論点②)。ただし全部は持たない(非効率)。元々地図データで持った方がよいものは持たせ、他は持ち主のシミュレーターが持つ。
- [確] 地図データ=「その場が何か」(陸・海・川・湖)の簡単なデータ。深さ・流量・幅などの細部は持ち主が別に持つ。川は最初からデータで持たなくてよい(交通網が作り、「川」として地図へ戻す)。
- [確 11-25 05:48] 世界地図の見せ方と、実際のデータのあり方は別。シミュレーターとして必要な存在は、世界地図としてデータを保有する必要がある。見せ方はそのデータを土台に使い、各層でどうするか(絵かポリゴンか等)を逐次動的に決める(ユーザー)。
