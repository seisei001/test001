# カード14 資料の地図と、この検索(ラグ)の運用ルール 【確定 2026-11-17】
検索語: ラグ RAG project_search 運用ルール 資料の地図 更新手順 STATE_LOG
出典: 世界ハニカム 現行状態カード(2026-11-20)

- 資料の役割: STATE.md=今の状態(検索の正)。OVERVIEW.md=概要設計と日付つき記録(履歴)。PRESENTATION.md=見せ方の設計(履歴)。POLICY.md=初期の作成方針(履歴)。管理ページ(apps/fantasy-war/)=作業一覧と判断待ち。
- 検索(Projectsの hub/cards/ と目次 hub/STATE.md)にはカード式の資料だけを入れる。長い原文は入れない(11-17の失敗)。経緯は STATE_LOG.md など原文を直接読む。
- 答える前に関連カードの状態(確定/案/未決/置換済み)を確かめる。未決を決定として扱わない。
- 記録の言葉: ユーザーの「決定・指示」=確定。感想・印象・「留保」=評価。「結論」の見出しは採用を決めたときだけ。
- 決めたあとの手順: ①STATE.mdのカード更新 ②OVERVIEW等に日付つきで追記 ③items.json更新 ④コミット→公開(200確認) ⑤検索の写しを入れ直す(design/make_cards.py でcards/を作り直し、Projectsの hub/cards/ へ。1文書=1カード、約700字以下、先頭に「検索語」の行)。
- 古い決定が置き換わったら消さず【置換済み】で残す(理由と日付つき)。
- 長い実験の経緯は STATE_LOG.md に移した(2026-11-20)。検索には入れない。
