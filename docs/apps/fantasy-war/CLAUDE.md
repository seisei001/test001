# ファンタジー世界戦争(世界ハニカム)専用の作業規則

適用範囲: docs/apps/fantasy-war/ と docs/apps/sekai-hex/ の作業だけ。他のアプリには適用しない。
この規則は短い「入口」。詳細は、ラグ(Projectsの hub/cards/)のカードと STATE.md にある。ユーザー(税理士・iPhoneのみ)の決定は、会話ではなくハブが正。

## ハブとラグの関係 【確定 11-24 ユーザー】
- ラグ(Projectsの hub/cards/ = repoの design/rag/)は、試行錯誤の中からハブに落として残した内容を整理したもの。言葉のcosine類似度で検索する。
- ハブの記録(STATE.md・OVERVIEW.md・items.json など)とラグが食い違う・衝突する時は、どちらかを黙って採らず、直さず、ユーザーに質問する。

## 世界地図の作り方(最上位仕様) 【確定 11-24 ユーザー】(STATE.md 「世界地図の作り方」。他のどの規則・試作より上位)
- 毎回ゼロから。PWGの起動から全実装を、統一した一本のアプリ(mapstyle/tools/make_world.py)で行う。データは塗り替え。残す絵はユーザーが言う。
- 地図データはシミュレーター側の完全なデータ。見せる地図は、そこから作るファンタジーらしい擬似の絵。今の作業は芸術性を高めること(完全さは求めない)。
- 順序: ①平坦な絵を先に描く → ②ローポリを作る → ③UVで貼る(一枚の絵に起伏をつける方法)。絵は一枚の平たい紙に下から上へ塗り重ねる(海と陸の境の色→森・川(川は戦場以下でポリゴンの部品へ(世界〜戦域は絵で代用)。街・城・特殊な地形・魔力・地脈もポリゴンの部品=絵には塗らない 11-24 23:17))。海は平坦・海岸線は高さ0。水の高さ(海・湖・川の水面と底)は交通網・天候のシミュレーターの仕事で、地図は持たない。
- 小手先の修正は禁止。仕様どおりにできない不都合は、直さず報告する。仕様に書かれていないことは質問する。作り方を無断で変えない。

## 超基礎概念(制作プロトコル) 【確定 11-21 ユーザー】
- 上位概念は、下位概念を縛らない。下位は自由に考えて、より良い物を作る。
- ただし、上位概念が下位概念に影響する、という当たり前の法則は無視しない。下位で分かったことが、上位を変えさせることもある。上位を変えるときは、理由と日付を記録し、ユーザーに伝える。
- 上位が未確定のまま、下位を積み上げない。仕様が固まる前に、作らない・発注しない。
- 工程: 概念→仕様の詰め→仕様の完成→詳細設計→詳細の実装→試験(外れたら原因の工程へ戻す)。

## 今・これから・過去と、親子の管理 【確定 11-24 06:57 ユーザー】(ハブの並び=items.json)
- 今・これからは、作業のたびに必ず更新する(各項目の now)。過去は、確定した時とボツにした時だけ更新する(st を past にし、理由を log に)。試行中の内容は「今」に置く。
- ハブは必要な時に読む辞書。読む時=今から派生した新しい作業を始める時。
- 名前: 試作中のプログラムに、ハブの並びの中で名前を付ける。派生を作る時は、名付けを必ずユーザーに確認し、確認した日を項目の named に書く(確認が「派生に入った」合図)。既存の項目に一括の確認は求めない。
- 派生: 子の名前は、親の名前の次に付ける(parent で入れ子にし、der:true を付ける)。バージョンでは分けない。並びの別作業は派生ではない。
- 親を変える時は、すべての子との連携を検討して実装する。子は、ボツか確定になるまで常に実装(親の変更に追従)する。
- 【Claude への指示】作業をしている最中に、いま作っている物(手を付けている項目)に派生の子が複数あると分かったら、Claude は作業を続ける前に、ユーザーへ「先に子供を決定してください(どれを確定・ボツにするか)」と警告する。報告の冒頭に書き、子の名前を並べる。分類の入れ物では警告しない。見落とさないよう、作業の始めに `python3 -I docs/apps/sekai-hex/design/check_now.py <手を付ける項目のid>` を補助に実行する。
- 【確認ボタン 11-24 07:52 ユーザー】作成中の今のアプリがあれば、その項目の下に確認ボタンを1つだけ作る(items.json の btn。種類 s=未決 か 決定のどちらか)。そこ以外(トップ・子の項目・過去)には作らない。過去のボツ・試作のリンクは、過去の管理(過去の項目の links。閲覧ページ「過去の検討」のリンク集)に1か所にまとめる。
- 旧「主と派生の台帳」(11-23)は【置換済み】(履歴は STATE.md 「主と派生の台帳」。消さない)。

## 作業の始め方(毎回)
1. STATE.md(docs/apps/sekai-hex/design/。今の状態。カード式)と、管理表 items.json(このフォルダ)の「今」の項目を読み、check_now.py(上の親子の管理)を実行する。
2. 話題ごとに、作業の前に project_search(ラグ)で検索し、カードの状態([確]/[案]/[評]/[ボツ]/[置])を確かめる。ラグは1カード=1トピックの現行仕様(2026-11-24 作り直し)。未決を決定として扱わない。
3. 作業は、始める前に管理表に項目を作り、終えたら状態と記録を更新する(全ての作業をハブで制御する)。ユーザーの指示・評価は、その場でSTATEに記録する(決定・指示=確定、感想・評価=評価)。
4. 決めたあとの手順: STATE.md(原文)→ 該当のラグ(docs/apps/sekai-hex/design/rag/<題名>.md。トピック別の現行仕様)をその場で書き換え → items.json → コミット・push → 公開サイトの200確認 → Projectsの hub/cards/<題名>.md へ project_write。

## 木・植生の二段方式 【確定 11-21 ユーザー指示】
- 一段目(地球の世界地図): ①ファンタジー地図が植生をどう見せているかをネットで調べ、上位概念としてハブに書く。②そのうえで、森を「塊」として世界地図でどう描いて見せるかを、別のコンセプトとして追求する。いまの丸と三角のデフォルメは良いが、村〜戦域・戦場の縮尺向き。衛星画像の深緑の滲み(点描の滲み)は求めていない。
- 二段目: 一段目ができたあとで、異世界・ファンタジーの上位概念を取り入れた応用を考える。「異世界とは何か」の定義は、二段目の前に決める(項目⓪)。
- 地球の植生を基礎の土台にしてよい(木が地球ならどう見せると見栄えが良いか、から始める)。

## 最終版の形 【確定 11-22 ユーザー】
- 最終版 = 回して見る3D表示(world3d.html)に、森・川などの要素と、ファンタジー要素の魔力・地脈を足したもの。航宙図(koutyuuzu0.html)は別のものとして開発中。
- 考察用の表示・比較ページは作らない。過去の試作・検討は管理表で『過去(解決済み)』に移してある(ファイルは残す)。新しい成果は最終版の3D表示に足す。

## 作り方・報告の約束
- 日本語。概要を先に短く。数式は使わない。実測と目視を分け、限界を書く。最後に次の一手を1つだけ。URLは独立した行に書く。
- 成果物はアーティファクトでなく、ハブ(docs/apps/fantasy-war/)に載せる。
- 世界・地図の成果は、グルグル回して見る3D表示(world3d.html。データは w3d/world<名>.json と .jpg、書き出しは FM_LP_DUMP)に載せて見せる 【確定 11-21 ユーザー指示】。平らな絵だけで終えない。
- 大きなデータはGoogleドライブ「ファンタジー世界戦争/世界データ」に保管する。
- コミットの末尾に、システムの帰属行を付ける。
- 世界地図の最新処理の手順は、スキル fantasy-map-publish にある。
- ラグの規則 【確定 11-24 ユーザー】: ボツになった内容も、有意なものは理由つきでラグに抽出する。ラグは言葉のcosine類似度で検索する(1カード=1トピック・見出しと検索語を具体的に)。文章は可能な限り整理してトークンを節約する。ラグには会話の経過を追記せず、整理した内容だけを書く。ラグの形=題名・検索語・状態+4区分。新しい派生の作業を作った時に「今」ができる/今の作業で未決の仕様ができた時に「これから」ができる/確定すると「今の確定」(特別な位置)になる/ボツにすると「過去」へ行く(確定が置き換わった時も過去へ。理由つき・消さない)。

## 過去の試作は辞書・ハブは目印 【確定 11-23 22:28 ユーザー】
- 過去の試作は『試行錯誤の辞書』。消さず・廃止と書かず、過去として残す。他の層(地方・戦域・戦場・隊・兵)や将来で使えるものがある。使い道はSTATE.mdの「過去の試作の辞書」に書く。
- ハブは『何をするかの目印(メルクマール)』。試作中のものと『どこまでやったか』を、管理表の各項目の『いま』と「過去の試作の辞書」に必ず残し、作業のたびに更新する。
- 決定で置き換えた時は【置換済み】で残す。『対象外』『外す』と書いて辞書の扱いを落とさない。
